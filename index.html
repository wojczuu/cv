Security · customer data · migrations · production - always the full pipeline below
01Spec
Scope, user flow, testable acceptance criteria, a do-not-touch list. Every number carries the command that produced it.
02Refute
A fresh agent with zero context and a model from another vendor try to break the spec: gaps, roles, permissions, boundary states, DB invariants. Then it locks.
03Split
Parallel tracks by file ownership. Shared code goes to a spine that lands first. One git worktree + one PR per track, merge order from dependencies.
04Build
Implementation agents write the code, tests first. Routine code on a cheaper model, architecture on the strongest one.
05Review
One reviewer agent + a second-vendor model, default verdict: refuted. Fixes loop until they pass. I read the final diff, never the summaries.
06Verify
Every UI change checked live in a headless browser. A read-only verifier confirms the release actually reached production.
Guardrails
gate in the PREach standard ships with a mechanical check: a grep in CI or an assertion on the live page. ratchetExisting violations counted as a baseline that may only shrink. hooksBlock a fix: commit without a test, and a PR no reviewer has seen. evidenceUnverified claims labelled as such; reviews cite file:line.
Lesson learned: requirements that came back were always the ones without a gate, and a gate counts only from its first real run.
